What's Building

A pipeline that finds every GitHub repo created since July 2021 with at least 50 stars, uses Claude to classify what each one is and what it's about, and tracks how stars and watchers move over time. All of it ends up as a few static JSON files that a web page can read.

The window starts more than a year before ChatGPT launched, so there's a real group of pre-boom repos to compare against everything created after it.

View on GitHub
The Problem

GitHub shows you repos one at a time. It won't tell you that half of the repos created in 2026 that crossed 50 stars are about AI, or that agent and MCP projects went from 275 in 2022 to more than 9,000 this year. Getting to numbers like that means classifying more than a quarter of a million repos and tracking how their stars change over time.

Each of those runs into a limit. The Search API stops at 1,000 results per query, one LLM call per repo would cost around $210 for the full set, and daily snapshots of every repo would reach 2.4 GB within three months. On top of that, the whole thing had to run without a server and cost close to nothing to host.

1Discover

Searches for repos created since July 2021 with 50 or more stars, excluding forks. Search caps every query at 1,000 results, so the crawl slices the window into date ranges small enough to stay under the cap and pages through each one. The star floor only applies at discovery, so a repo that later drops below 50 stays tracked and the trends don't only count the repos that kept their stars.

2Snapshot

Pulls stars, forks and watchers for 100 repos per GraphQL request, keyed by node ID so a renamed repo still matches. Watchers have to come from GraphQL because the REST API returns the star count in that field. A full pass over every repo takes about two hours and fits inside the free rate limit.

3Classify

Claude Haiku 4.5 sorts each repo by what it is (library, CLI tool, web app and so on) and what it's about, and flags whether it's AI related. Packing 20 repos into each call and sending them through the Batch API classified all 262,902 for $56.65. A strict schema keeps every answer inside the taxonomy, and repos only get re-classified when their description changes.

4Store

The database keeps metrics in three tiers: one anchor snapshot per repo from day one, weekly snapshots for the last 90 days, and monthly snapshots forever. That keeps both recent detail and the long-run trend while the database stays around 340 MB, about a seventh of what daily snapshots would take.

5Aggregate

One script is the only thing that reads the database. It collapses hundreds of thousands of repos and millions of metric rows into category and domain counts, trends per snapshot and the top 100 repos in each category, about 2 MB of JSON in total. Swapping the database later means changing this one file.

6Publish

The page loads those JSON files and never queries a database, so hosting is free and there's no backend to run. A visitor downloads a few hundred kilobytes to see the whole picture.

How It Runs

Daily

1 Discover 3 Classify 5 Aggregate 6 Publish

Picks up repos that crossed 50 stars in the last few days and classifies them with the regular API before the page redeploys. It takes minutes and costs a few cents.

Weekly

2 Snapshot 4 Store

Refreshes metrics for every tracked repo and applies the retention rules. Both jobs run on GitHub Actions and store the database in Cloudflare R2, and they share a lock so they never write to it at the same time.
